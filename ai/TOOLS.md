# 측정·기준 계산 도구 사용법

> 원래 `body_face_test` 테스트 키트의 설명서입니다. 이제 이 `ai` 폴더가 원본이며, 명령은 모두 `ai` 폴더에서 실행합니다.
> AI 서버 실행·백엔드 연결은 `README.md` 를 보세요.

# 얼굴형 · 체형 무료 테스트 키트 (MediaPipe)

유료 API를 붙이기 전에 **Google MediaPipe(무료, Apache 2.0)** 로 얼굴형·체형 추출을 먼저 시험해 보는 도구입니다.
모든 분석은 **내 컴퓨터 안에서만** 돌아가며, 사진이 외부 서버로 전송되지 않습니다.

> ⚠️ 분류 체계는 팀 확정안(얼굴형 6종, 체형은 Size Korea 20대 남성 4종)을 따르지만, **판정 기준값은 전부 임시값**입니다.
> 팀이 직접 라벨을 붙인 사진으로 `calibrate.py` 를 돌려 보정해야 합니다.

---

## 1. 설치 (최초 1회, 5분)

Python 3.10 이상이 필요합니다.

```bash
cd body_face_test
python -m venv .venv
# Windows:  .venv\Scripts\activate
# Mac/Linux: source .venv/bin/activate
pip install -r requirements.txt
python download_models.py          # 모델 2개(약 13MB)를 Google 공식 저장소에서 받음
```

## 2. 사진 1장 테스트

```bash
python run_test.py face 내얼굴.jpg
python run_test.py body 내전신.jpg --height 175
```

- 화면에 결과 JSON이 나오고, `results/` 폴더에 **측정선이 그려진 이미지**가 저장됩니다.
- 얼굴형 결과에는 1위 판정과 함께 `candidates`(예: 계란형 77%, 직사각형 19%)가 나옵니다.
  1위 확률이 60% 미만이면 `borderline` 문구가 붙습니다 → 두 유형의 경계에 있는 얼굴이라는 뜻입니다.
- `usable: false` 는 고개 각도·표정(입 벌림, 웃음) 때문에 **믿기 어려운 사진**이라는 뜻입니다. 판정은 나오지만 재촬영을 권장합니다.

### 같은 사람 사진 여러 장으로 종합 판정 (권장)

```bash
python run_test.py face-multi 사진1.jpg 사진2.jpg 사진3.jpg
python run_test.py face-multi photos/kim        # 폴더도 가능
```
품질 검사를 통과한 사진들의 측정값 **중앙값**으로 최종 판정합니다. 앱에서도 3~5장을 연속 촬영해 이 방식으로 판정하는 걸 권장합니다.
종합 판정의 확률(`candidates`)은 사용한 장수만큼 측정 흔들림을 줄여서 계산합니다 (중앙값 표준오차 ≈ 1.25σ/√n).
  → 선이 이마·광대·턱, 어깨·허리·골반에 제대로 걸렸는지 눈으로 꼭 확인하세요.
- `warnings` 에 나오는 문구(고개 각도, 사진 잘림, 팔 붙음 등)는 그대로 앱의 **촬영 가이드 문구**로 쓸 수 있습니다.

## 2-1. 실시간 웹캠 모드 (얼굴형)

```bash
python run_live.py
```
노트북 웹캠 화면이 뜨고, 위쪽에 안내 문구가 나옵니다.

1. 가운데 점선 타원에 얼굴을 맞춥니다. 얼굴 윤곽선이 **초록색**이면 통과, **빨간색**이면 위쪽 안내를 따르세요.
   (예: "정면을 봐 주세요", "턱을 조금 들어 주세요", "입을 다물어 주세요", "조금 뒤로 가 주세요")
2. 통과한 상태로 2초쯤 있으면 아래 막대가 차오르며 **1회차** 측정값 6개가 모입니다.
3. "고개를 살짝 옆으로 돌렸다가 다시 정면을 봐 주세요" 안내가 나오면 그대로 따라 합니다 → **2회차** 측정.
   (고개를 돌리지 않아도 5초 뒤 자동으로 넘어가지만, 돌렸다 돌아오는 게 정확도에 더 좋습니다)
4. 1·2회차 결과가 **같으면 끝**, **다르면 3회차**까지 측정합니다.
5. **회차별 중앙값의 중앙값**으로 최종 얼굴형 + 유형별 확률 + 회차별 결과 + 특징이 표시됩니다.

> 왜 여러 회차? 한 회차의 6프레임은 2초 안에 같은 자세로 찍혀 사실상 같은 사진입니다.
> 회차마다 자세를 다시 잡으면 고개 각도·거리 같은 오차가 회차마다 달라져 중앙값에서 상쇄됩니다.

| 키 | 동작 |
|---|---|
| `R` | 다시 측정 |
| `S` | 결과 저장 (`results/live_날짜시간.json`) |
| `D` | 측정값·고개 각도·표정 점수 표시 (디버그) |
| `Q` / `ESC` | 종료 |

| 옵션 | 의미 |
|---|---|
| `--camera 1` | 카메라가 여러 개일 때 번호 변경 |
| `--rounds auto` | 측정 회차. `auto`(기본: 2회 일치하면 끝, 다르면 3회) 또는 `1`, `2`, `3` 고정 |
| `--frames 6` | 회차당 모을 프레임 수 |
| `--interval 0.3` | 프레임 사이 최소 간격(초) |
| `--person kim` | 측정이 끝나면 자동 저장 + `live_measurements.csv` 에 누적 (아래 참고) |
| `--video 영상.mp4` | 웹캠 대신 영상 파일 (휴대폰으로 찍은 셀카 영상 등) |
| `--no-window` | 화면 없이 실행, 결과만 출력 (영상 파일 테스트용) |

- **영상은 저장하지 않습니다.** 저장되는 건 측정값과 판정 결과뿐입니다.
- 품질 기준(얼굴 크기, 중앙, 밝기, 움직임 등)은 `config.py` 의 `LIVE_...` 값에서 조정합니다.
- **비교 실험·신뢰도 계산에 쓰기**: `--person kim` 으로 측정하면 `live_measurements.csv` 에 **회차마다 한 줄씩** 쌓입니다.
  이 데이터가 있으면 `fit_population.py` 가 특징별 신뢰도를 계산합니다 (5-1 참고).
  ```bash
  python consistency.py live_measurements.csv
  python compare_methods.py live_measurements.csv --labels person_labels.csv
  ```
  ※ 한 번 측정한 8개 프레임은 몇 초 안에 찍힌 것이라 서로 비슷합니다. 사람마다 **여러 번(세션)** 측정해야 실험이 의미 있습니다.
- **카메라가 안 열릴 때**: 줌·카톡 등 다른 프로그램이 카메라를 쓰고 있는지 확인. Mac 은 시스템 설정 → 개인정보 보호 및 보안 → 카메라에서 터미널(또는 VS Code)을 허용해야 합니다.

## 2-2. 실시간 체형 모드

```bash
python run_live_body.py --height 175                    # 웹캠
python run_live_body.py --height 175 --video 전신.mp4    # 휴대폰으로 찍은 영상 (권장)
```
`--height`(키, cm)는 필수입니다. 체형은 키 대비 비율로 판정하기 때문입니다.

**진행 순서**
1. **자세 안내** — 화면 위쪽에 큰 글씨로 안내가 나옵니다.
   ("발끝까지 보이게 뒤로 가 주세요", "머리 위가 잘렸어요", "조금 더 가까이 와 주세요", "화면 가운데에 서 주세요",
   "카메라 정면으로 서 주세요", "몸을 똑바로 세워 주세요", "팔을 몸에서 살짝 떼 주세요 (A자 자세)", "잠시 움직이지 말아 주세요")
   머리는 위쪽 점선 아래, 발은 아래쪽 점선 위에 오게 서세요.
2. **카운트다운** — 자세가 맞으면 3초 카운트다운. 그동안 자세가 흐트러지면 1단계로 돌아갑니다.
3. **1회차 수집** — 0.3초 간격으로 좋은 프레임 5개의 측정값을 모읍니다.
4. **자리 다시 잡기** — "한 걸음 옆으로 나갔다가 다시 제자리에 서 주세요" → 돌아오면 1.5초 카운트다운 후 **2회차**.
   (자리를 안 옮겨도 6초 뒤 자동 진행되지만, 다시 서는 게 정확도에 더 좋습니다)
5. 1·2회차 결과가 **같으면 끝**, **다르면 3회차**까지 → **회차별 중앙값의 중앙값**으로 최종 판정.
6. **결과** — 체형 + 판정 이유 + 회차별 결과 + Size Korea 평균 대비 비교 + 정면 폭(cm).

> 왜 여러 회차? 한 회차의 5프레임은 1~2초 안에 같은 자세로 찍혀 거의 같은 사진입니다.
> 매번 다시 서면 서는 위치·자세·팔 각도가 조금씩 달라져, 그 오차가 중앙값에서 상쇄됩니다.

| 키 | 동작 |
|---|---|
| `R` | 다시 측정 |
| `S` | 결과 저장 (`results/live_body_날짜시간.json`) |
| `D` | 마스크·측정선 표시 켜기/끄기 |
| `Q` / `ESC` | 종료 |

| 옵션 | 의미 |
|---|---|
| `--video 파일` | 웹캠 대신 영상 파일 |
| `--rotate 90` | 영상이 옆으로 누워 보이면 회전 (90 / 180 / 270, 시계 방향) |
| `--person kim` | 측정이 끝나면 자동 저장 + `live_body_measurements.csv` 에 누적 |
| `--rounds auto` | 측정 회차. `auto`(기본: 2회 일치하면 끝, 다르면 3회) 또는 `1`, `2`, `3` 고정 |
| `--allow-arms-down` | 팔이 몸에 붙어 있어도 측정 (A자 자세 검사 끄기) |
| `--beep` | 카운트다운 시작·측정 시작·완료 때 소리 (멀리 서 있을 때 유용) |
| `--frames 5`, `--countdown 3` | 회차당 모을 프레임 수, 첫 회차 카운트다운 시간 |
| `--no-window` | 화면 없이 실행, 결과만 출력 |

**어떻게 찍어야 하나 (가장 중요)**
- **노트북 웹캠은 비추천**: 가로 화면이라 전신을 담으려면 3m 이상 떨어져야 하고, 그러면 몸이 작게 잡혀 정확도가 떨어집니다.
- **권장 방법 ① 휴대폰 영상**: 휴대폰을 **세로로, 허리 높이에** 세워 두고 2~3m 떨어져 10초 정도 찍은 뒤 `--video` 로 넣기.
  카메라를 위·아래로 기울이면 다리·몸통 비율이 왜곡되니 휴대폰을 바닥과 수직으로 세우세요.
- **권장 방법 ② 휴대폰을 웹캠으로**: Mac 연속성 카메라, Windows Phone Link·DroidCam 등으로 휴대폰을 웹캠처럼 연결 → `--camera 1` 등으로 선택.
- 몸에 붙는 옷, 팔은 몸에서 살짝 뗀 A자 자세, 다리는 살짝 벌리기, 단색 배경, 혼자 나오게.

**비교 실험에 쓰기**: `--person kim` 으로 측정하면 `live_body_measurements.csv` 에 **회차마다 한 줄씩** 쌓입니다.
사람마다 여러 번(다른 시간·옷차림) 측정해 두면 일관성 확인과 `fit_body_population.py` 기준 맞추기에 모두 쓸 수 있습니다.
```bash
python consistency.py live_body_measurements.csv      # 같은 사람 결과가 일관적인지
```
정답 체형을 `label` 열에 적으면 `calibrate.py live_body_measurements.csv` 로 기준값 보정도 할 수 있습니다.

## 3. 촬영 규칙 (정확도의 80%는 여기서 결정됨)

| | 얼굴 | 전신 |
|---|---|---|
| 자세 | 정면, 고개 수평, 무표정 | 정면, 똑바로 선 자세, **팔을 몸에서 살짝 뗀 A자 자세** |
| 카메라 | 눈높이, 팔 길이 거리 (광각 셀카 왜곡 주의) | 배꼽 높이, 2~3m 거리, 머리 위·발 아래 여백 |
| 가림 | 앞머리를 넘기고 이마·턱선이 보이게, 안경 벗기 | 몸에 붙는 옷 (헐렁한 후드·코트 X) |
| 배경/조명 | 밝고 균일한 조명 | 단색 배경, 혼자 찍기 |

## 4. 분류 체계와 결과 값 읽는 법

### 얼굴형 6종 (팀 확정안)

> 기본 판정은 **평균 대비 방식(relative)** 입니다 → 유형별 기준은 **5-1** 참고.
> 아래 표는 예전 고정 규칙(`FACE_CLASSIFIER = "rules"`) 기준입니다.

| 분류 | 판정 기준 (임시값, `config.py` FACE_RULES) |
|---|---|
| 직사각형 | 얼굴이 길고(`length_ratio` ≥ 1.30) 턱이 넓거나 각짐 / 또는 길지 않아도 턱이 넓고 각짐 |
| 긴형 | 얼굴이 길고 턱선이 부드러움 |
| 다이아몬드형 | 이마·턱이 모두 좁고 광대만 넓음 |
| 하트형 | 이마가 턱보다 훨씬 넓고 턱끝이 뾰족함 |
| 둥근형 | 얼굴 길이가 폭에 비해 짧음(`length_ratio` ≤ 1.10) |
| 계란형 | 위 어디에도 해당하지 않는 균형형 |

| 값 | 의미 |
|---|---|
| `length_ratio` | 얼굴 길이 ÷ 광대 폭 (클수록 긴 얼굴). ※ MediaPipe 메시 맨 위가 헤어라인보다 낮아서 실제보다 작게 나옴 |
| `forehead_ratio` | 이마 폭 ÷ 광대 폭 |
| `jaw_ratio` | 턱 폭 ÷ 광대 폭 (클수록 넓은 턱) |
| `chin_ratio` | 턱끝 폭 ÷ 턱 폭 (작을수록 뾰족한 턱) |
| `jaw_angle_deg` | 광대→턱 모서리→턱끝 각도 (작을수록 각진 턱) |
| `head_pose_deg` | 고개 각도 (품질 검사용) |

### 체형 4종 — Size Korea 20대 남성 Pattern

> 팀 기준(`body_population.json`)을 만들면 **상대 판정**으로 바뀝니다 → **5-2** 참고.
> 아래 판정 기준 표는 팀 기준이 없을 때 쓰는 예전 규칙(Size Korea 절대 기준)입니다.

Size Korea 는 키에 대한 비율을 **평균(표준체형)** 과 비교해 Pattern 을 나눕니다.
이 키트도 같은 방식으로, 사진에서 잰 값을 **키 대비 비율**로 바꾼 뒤 Size Korea 20대 남성 평균과 비교합니다.
(기준값: `config.py` 의 `SIZE_KOREA_REF_MM`, 출처 sizekorea.kr › 한국인의 체형 분류 › 20대 남자)

| 분류 | Size Korea 설명 (요약) | 키트 판정 기준 (임시값, BODY_RULES) |
|---|---|---|
| 표준체형 | 평균 체형 (비교 기준) | 어깨·몸통 편차가 모두 ±5% 이내 |
| 작은 역삼각체형 | 가는 몸통, 넓은 어깨 | 몸통이 평균 이하 + (어깨 편차 − 몸통 편차) ≥ +6% |
| 큰 사각체형 | 굵은 몸통 | 몸통 굵기 편차 ≥ +8% |
| 사각체형 | 위아래 고른 몸통, 보통 어깨 | 나머지 |

| 값 | 의미 |
|---|---|
| `shoulder_dev` | 어깨 폭(삼각근 바깥, Size Korea '위팔사이너비')의 평균 대비 편차. +0.05 = 키 대비 5% 넓음 |
| `waist_dev`, `hip_dev` | 허리·엉덩이 정면 폭의 평균 대비 편차 |
| `trunk_dev` | 몸통 굵기 = 허리·엉덩이 편차의 평균 |
| `taper_dev` | 허리÷엉덩이 비율의 편차 (+면 허리가 상대적으로 굵음) |
| `arm_dev` | 팔 길이 편차 |
| `limb_dev` | 샅높이 대비 몸통 길이 편차 (−면 다리가 긴 편 = Size Korea '긴 지체'). 카메라 높이에 민감해서 판정에는 안 씀 |
| `*_cm` | 키로 환산한 실제 길이 (참고용) |
| `compare_to_size_korea` | 위 편차를 사람이 읽기 쉬운 문장으로 바꾼 것 (앱 결과 화면 문구로 활용 가능) |

> 사진 한 장으로 재는 것은 **정면 폭**이지 줄자로 재는 둘레·두께가 아닙니다.
> Size Korea 가 Pattern 을 나눌 때 쓰는 항목 중 **두께, 어깨 처짐, 머리 크기, 엉덩이 길이**는 정면 사진으로 잴 수 없어서 빠져 있습니다.

## 5. 결과가 사진마다 다르게 나올 때

얼굴형은 원래 경계가 흐린 분류라서, 측정값이 기준선 근처에 있는 얼굴은 작은 차이에도 판정이 바뀝니다. 키트는 이를 줄이기 위해:

1. **3D 정면화** — 3D 랜드마크를 정면을 보는 얼굴로 돌려 세운 뒤 잽니다 (`FACE_FRONTALIZE`).
2. **4회 측정 평균** — 원본·좌우반전·얼굴 확대본에서 각각 재서 평균합니다 (`FACE_TTA`).
3. **촬영 품질 검사** — 고개 각도, 입 벌림, 웃음을 검사해 `usable: false` 로 표시합니다.
4. **확률로 표시** — 측정 오차만큼 값을 흔들어 판정한 비율을 `candidates` 로 보여줍니다.
5. **여러 장 종합** — `face-multi` 로 여러 장의 중앙값을 씁니다.

그래도 흔들리면 대부분 아래 원인입니다.

| 원인 | 왜 흔들리나 | 해결 |
|---|---|---|
| 연예인·SNS 사진 | 각도·조명·렌즈·보정(성형 필터, 턱 깎기 보정)이 제각각 | 테스트는 **직접 같은 조건으로 찍은 사진**으로 |
| 가까이서 찍은 셀카 | 광각 렌즈 왜곡으로 얼굴 가운데가 커지고 턱이 좁아 보임 | 1m 이상 떨어져 2배 줌 또는 다른 사람이 찍기 |
| 표정 | 웃으면 볼·턱이 넓어지고, 입을 벌리면 얼굴이 길어짐 | 무표정, 입 다물기 |
| 머리카락·수염 | 이마·턱선을 가리면 윤곽 추정이 불안정 | 앞머리 넘기기, 수염은 판정 신뢰도 낮음 |
| 기준값 경계 | 측정값이 기준선 바로 옆 | `candidates` 2순위를 함께 보여주고 사용자가 고르게 |

## 5-1. 계란형이 너무 많이 나올 때 (판정 방식과 평균 기준 맞추기)

**원인**: 예전 판정(`rules`)은 "길이 1.30 이상이면 긴형" 같은 고정 기준을 위에서부터 검사하고,
어디에도 안 걸리면 계란형으로 보냈습니다. 실제 측정값은 대부분 그 기준들 사이에 있어서 계란형으로 몰렸습니다.

**바뀐 판정(`relative`, 기본값)**: 평균 얼굴과 비교해 **가장 두드러진 특징**의 유형으로 판정합니다.

| 유형 | 평균보다 이런 얼굴 |
|---|---|
| 긴형 | 얼굴이 길고 턱선이 부드러움 |
| 직사각형 | 얼굴이 길고 턱이 넓고 각짐 / 또는 길이와 무관하게 턱이 넓고 각짐 |
| 둥근형 | 얼굴이 짧고 턱선이 둥글고 턱끝이 넓음 |
| 하트형 | 이마가 넓고 턱이 좁고 턱끝이 뾰족함 |
| 다이아몬드형 | 이마와 턱이 모두 좁음 (광대만 넓음) |
| 계란형 | 어느 쪽으로도 크게 두드러지지 않는 **균형형** |

결과에는 `vs_average`(평균 대비 수치)와 `reason`(예: "얼굴이 긴 편, 턱선이 각진 편")이 함께 나옵니다.

**평균 기준을 팀 데이터로 맞추기 (중요)**
`config.py` 의 평균값은 테스트 얼굴 몇 명으로 잡은 임시값입니다. 팀이 모은 측정값으로 다시 잡으세요.

```bash
# 1) 지금 분포 확인 (라벨 없어도 됨, 사람 15명 이상 / 권장 30명 이상)
python fit_population.py face_features.csv live_measurements.csv

# 2) 계란형 목표 비율을 정해 저장 → face_population.json 이 생기고 모든 실행에 자동 적용
python fit_population.py face_features.csv live_measurements.csv --oval-share 0.25 --save
```
- 출력에 **예전 규칙 / 임시 평균 / 팀 데이터 평균** 세 가지 방식의 유형 분포가 나란히 나와서 비교할 수 있습니다.
  CSV 에 `label`(정답) 열이 있으면 방식별 정확도도 함께 나옵니다.
- `--oval-share` 는 "계란형을 몇 % 정도로 둘지"입니다. 계란형은 '평균형'이라 어느 정도는 나오는 게 자연스럽습니다.
  몇 %가 맞는지는 정답 라벨로 확인하는 게 가장 좋습니다 (정확도가 가장 높은 비율 선택).
- 되돌리려면 `face_population.json` 을 지우면 됩니다. 예전 방식으로 돌아가려면 `config.py` 에서 `FACE_CLASSIFIER = "rules"`.

**같은 사람인데 잴 때마다 유형이 바뀔 때 — 특징별 신뢰도**
특징마다 측정이 흔들리는 정도가 다릅니다. 특히 **이마 폭**은 사람끼리 차이가 작아서,
측정 오차가 "이마가 넓은 편/좁은 편"으로 잘못 읽히기 쉽습니다 (하트형·다이아몬드형이 들쭉날쭉한 주된 원인).
그래서 판정할 때 특징마다 **신뢰도 가중치**를 곱합니다. 기본값은 임시값(이마 0.5)이고,
같은 사람을 여러 번 잰 데이터가 있으면 `fit_population.py` 가 자동으로 계산합니다.

```bash
# 사람마다(5명 이상) 여러 번 측정 → 회차 데이터가 쌓임
python run_live.py --person kim
python run_live.py --person lee
...
# 신뢰도·흔들림·평균을 계산해 저장
python fit_population.py live_measurements.csv --save
```
출력에는 특징별 `사람 간 퍼짐 / 같은 사람 흔들림 / 신뢰도` 와 함께,
**1회·2회·3회 측정 중앙값일 때 같은 사람에게 같은 결과가 나올 비율(예측)** 이 나옵니다.
저장하면 신뢰도 가중치와 회차 간 흔들림(판정 확률 계산용)도 함께 적용됩니다.

**더 세밀하게 조정하려면** (`config.py`)
- `FACE_OVAL_RADIUS`: 키우면 계란형 ↑, 줄이면 다른 유형 ↑ (fit_population.py 가 추천값을 저장해 줌)
- `FACE_FEATURE_WEIGHTS`: 특징별 신뢰도 (fit_population.py 로 계산되면 그 값이 우선)
- `FACE_PROTOTYPES`: 유형별로 어떤 특징을 얼마나 중요하게 볼지. 예) 하트형이 너무 적으면 하트형의 `jaw_ratio` 숫자를 키움
- 길지 않은데 턱이 각진 얼굴을 직사각형으로 보내는 규칙은 `rectangle` 의 두 번째 줄입니다. (팀 결정 — 지우면 그런 얼굴은 다른 유형으로 감)

## 5-2. 체형이 한쪽으로 쏠릴 때 (작은 역삼각·표준체형이 안 나옴)

**원인**: 예전 규칙은 "Size Korea 평균에서 ±5% 이내면 표준", "몸통이 평균 이하로 가늘고 어깨가 넓으면 작은 역삼각"처럼
**Size Korea 실측 평균을 기준점**으로 씁니다. 그런데 사진 측정은 **옷 두께** 때문에 몸통이 실제보다 굵게 재지고,
머리카락·신발 때문에 키 환산이 달라지는 등 **모든 사람에게 공통으로 들어가는 치우침**이 있습니다.
몸통이 평균보다 6%만 굵게 재져도 작은 역삼각체형은 18% → 4%로 줄고 큰 사각체형이 늘어납니다.

**해결 — 팀 데이터 기준 상대 판정**: 팀이 잰 사람들의 평균을 기준점으로 삼아 공통 치우침을 상쇄하고,
유형 비율이 Size Korea 20대 남성 구성비와 비슷해지도록 기준을 계산합니다.

```bash
# 1) 지금 분포·치우침 확인 (라벨 없어도 됨, 15명 이상 / 권장 30명 이상)
python fit_body_population.py body_features.csv live_body_measurements.csv

# 2) 저장 → body_population.json 생성, 이후 모든 체형 판정이 상대 판정으로 바뀜
python fit_body_population.py body_features.csv live_body_measurements.csv --save
```
- 출력 맨 위의 **측정 치우침 진단**에서 "몸통이 Size Korea 평균보다 +10% 굵게 재짐" 같은 경향을 확인할 수 있습니다.
- **목표 비율**: 표준체형 20%(`--standard-share`), 나머지는 Size Korea 20대 남성 구성비
  (작은 역삼각 30.8 : 큰 사각 33.2 : 사각 35.9, `--sk-shares` 로 변경 가능).
- 판정 기준

| 체형 | 팀 평균 대비 |
|---|---|
| 표준체형 | 어깨·몸통 굵기가 모두 팀 평균에 가까움 |
| 큰 사각체형 | 몸통이 평균보다 굵은 편 |
| 작은 역삼각체형 | 몸통 굵기에 비해 어깨가 넓은 편 |
| 사각체형 | 나머지 (어깨와 몸통 폭이 비슷한 편) |

- 결과에 `reason`(예: "몸통이 가는 편, 몸통에 비해 어깨가 넓은 편")과 `vs_team_average` 가 함께 나옵니다.
  Size Korea 실측 평균과의 비교(`compare_to_size_korea`)는 참고용으로 그대로 표시됩니다.
- **팀 기준이 없으면 예전 규칙으로 판정**합니다 (임시 기준으로 상대 판정을 하면 오히려 더 쏠리기 때문).
- **전제**: 팀이 측정한 사람들의 체형 분포가 Size Korea 20대 남성과 비슷하다고 가정합니다.
  측정 대상이 특정 체형에 몰려 있으면(예: 운동부만) 비율 맞추기가 왜곡되니, 다양한 사람을 측정하세요.
- 되돌리려면 `body_population.json` 을 지우면 됩니다.

## 6. 추천 테스트 순서

### 1단계: 재현성 테스트 (팀원 4명, 하루)
같은 사람을 조건을 조금씩 바꿔 5~10장씩 찍고 결과가 흔들리지 않는지 봅니다.

1. 사진을 `photos/face/` (또는 `photos/body/`)에 넣고, `labels_face_example.csv` 를 참고해 `file,person_id` 를 적습니다. (label 은 비워도 됨)
2. 실행
   ```bash
   python run_test.py face-batch photos/face --labels labels_face.csv -o face_features.csv
   python consistency.py face_features.csv
   ```
3. **일치율이 낮으면** → 촬영 규칙을 더 엄격하게 하거나(경고 기준 강화), 기준값이 그 사람 근처 경계에 걸린 것.
4. 출력 마지막의 '표준편차 평균' 값을 `config.py` 의 `FACE_FEATURE_NOISE` 에 넣으면, 판정 확률이 실제 흔들림을 반영하게 됩니다.

### 2단계: 정확도 보정 (지인 포함 50~100명)
1. 팀원 2~3명이 각자 **따로** 사진을 보고 얼굴형/체형 라벨을 붙인 뒤 다수결로 `label` 을 정합니다. `label` 에는 위 표의 한글 이름(예: `직사각형`, `작은 역삼각체형`)을 그대로 적으면 됩니다.
   (라벨 기준을 문서로 먼저 정해 두세요. 사람마다 다르게 붙이면 어떤 모델도 못 맞춥니다.)
2. 실행
   ```bash
   python run_test.py face-batch photos/face --labels labels_face.csv -o face_features.csv
   python calibrate.py face_features.csv
   ```
3. 출력에서
   - `[1]` = 지금 임시 규칙의 정확도
   - `[2]` = 데이터로 학습한 모델의 정확도 (사람 단위 교차검증)
   - `[3]` = 데이터가 찾아낸 판정 기준 → 이 숫자를 보고 `config.py` 의 기준값을 고칩니다.
4. 고친 뒤 다시 batch → calibrate 를 돌려 `[1]` 점수가 올라갔는지 확인. 이 전후 비교표가 포트폴리오 자료가 됩니다.

> 체형 batch 는 사람마다 키가 필요합니다 → labels CSV 의 `height_cm` 열에 적거나 `--height` 로 일괄 지정.

## 7. 비교 실험: 사진 1장 vs 여러 장 종합, 어느 쪽이 더 정확한가

앱에서 사진을 몇 장 찍게 할지 정하는 근거를 숫자로 만드는 실험입니다.

### 7-1. 사진 준비 — 사람마다 폴더 하나 (폴더 이름 = person_id)

```
photos/face_exp/
├─ kim/    kim_01.jpg ~ kim_08.jpg
├─ lee/    ...
└─ park/   ...
```
- 사람당 **8~10장 권장** (최소 5장). 인원은 10명 이상이면 좋습니다.
- 같은 날 한 번에 연사로 찍지 말고, **조건을 조금씩 바꿔서** 찍으세요. (찍을 때마다 다시 자리 잡기, 다른 시간대, 다른 조명 1~2장)
  실제 사용자가 앱에서 찍는 상황과 비슷해야 실험 결과가 의미 있습니다.
- 촬영 규칙(정면·무표정·이마 보이게)은 지키되, 일부러 완벽하게 맞추려 하지 않아도 됩니다.

### 7-2. 정답 파일 (선택, 있으면 '정확도'까지 계산)

`person_labels_example.csv` 를 복사해 `person_labels.csv` 로 만들고, 사람별 정답 얼굴형을 적습니다.
팀원 2~3명이 **각자 따로** 판단한 뒤 다수결로 정하세요.

```
person_id,label
kim,계란형
lee,직사각형
```

### 7-3. 실행

```bash
python compare_methods.py photos/face_exp --labels person_labels.csv
```
- 처음에는 사진마다 측정하느라 시간이 걸립니다 (사진 100장 기준 수 분). 측정값은 `photos/face_exp/_measurements.csv` 에 저장되고 다음부터 재사용됩니다. 사진을 바꿨다면 `--refresh`.
- 정답 파일 없이 돌리면 **일관성**만 비교합니다.

| 옵션 | 의미 |
|---|---|
| `--k 1 3 5` | 비교할 장수 (기본 1, 3, 5) |
| `--draws 300` | 사람마다 사진 조합을 무작위로 뽑는 횟수 |
| `--include-unusable` | 품질 검사(고개 각도·표정)에 걸린 사진도 포함 — 실제 사용자가 대충 찍는 상황 가정 |
| `-o compare_out` | 결과 저장 폴더 |

### 7-4. 결과

`compare_out/` 폴더에 저장됩니다.

| 파일 | 내용 |
|---|---|
| `compare_report.md` | 요약 표 + 읽는 법 (발표 자료에 그대로 사용 가능) |
| `compare_chart.png` | 방식별 정확도·일관성 막대 그래프 |
| `compare_summary.csv` | 요약 수치 |
| `compare_detail.csv` | 사람별 결과 (누가 흔들리는지) |

비교하는 방식은 5가지입니다: **1장**, **3장 중앙값**, **3장 투표**, **5장 중앙값**, **5장 투표**
(중앙값 = 측정값을 합친 뒤 판정, 투표 = 각각 판정한 뒤 다수결)

| 지표 | 의미 |
|---|---|
| 정확도 | 정답과 같은 판정이 나온 비율 |
| 일관성 | 같은 사람에서 가장 많이 나온 판정과 같은 결과가 나온 비율 |
| 흔들림 | 판정 직전 측정값(length_ratio)의 사람 내 표준편차. 이론상 √장수 에 비례해 줄어듦 |

**결과 해석 팁**
- 일관성은 높은데 정확도가 낮으면 → 측정은 안정적인데 **판정 기준값이 틀린 것** → `calibrate.py` 로 보정.
- 3장→5장에서 거의 안 오르면 → **3장으로 충분**하다는 근거 (사용자 부담 ↓).
- `--include-unusable` 를 켰을 때와 껐을 때를 비교하면 → **품질 검사의 효과**도 보여줄 수 있습니다.

## 9. 알려진 한계

- **헐렁한 옷**: 사람 영역 마스크가 옷 윤곽을 따라가므로 허리·골반 폭이 커집니다. (예: 스웨터 밑단을 골반으로 잡음)
- **팔이 몸에 붙은 사진**: 팔 영역을 지우고 재지만, 팔과 몸통이 겹친 부분은 몸통도 일부 깎일 수 있습니다.
- **키 환산**: 체형 판정이 '키 대비 비율'이라 **머리 위나 발끝이 잘리면 모든 편차가 틀어집니다.** 전신이 다 나오게 찍는 게 필수입니다.
- **옷 두께**: 옷 윤곽을 재기 때문에 실제보다 몸통이 굵게 나옵니다(→ 큰 사각체형 쪽으로 치우침). 보정할 때 이 경향을 꼭 확인하세요.
- **원피스·긴 코트**: 다리 사이가 보이지 않아 샅높이는 측정하지 않습니다.
- **얼굴 길이**: 메시 상단이 헤어라인이 아니라서 절대 길이는 짧게 나옵니다. 모든 사진에 동일하게 적용되므로 비교·분류에는 문제 없습니다.
- **광각 셀카**: 가까이서 찍은 셀카는 얼굴 중앙이 커 보이는 왜곡이 있어 비율이 달라집니다.
