## 2. Mobile 역할 & 기술 스택

- **통신 구조**: `[Mobile 앱] ↔ [Backend 서버(박준희)] ↔ [AI 서버(김민건·최기완)]`
  - Mobile은 **Backend API만 호출**하며 AI 서버와 직접 통신하지 않음.
  - 대회 MVP는 **비로그인 게스트 세션(`sessionId`)** 기반.
- **사용 기술**:
  - **React Native + Expo + TypeScript**
  - **화면 이동**: Expo Router 또는 React Navigation
  - **전역 상태 관리**: Zustand 또는 React Context (`sessionId`, 로컬 사진 URI, 분석 결과 `result` 등 보관. 앱 재시작 시 새 세션 시작 권장)
  - **카메라 / 앨범**: `expo-camera`, `expo-image-picker`
  - **네트워크 통신**: 기본 `fetch` + `FormData` (타임아웃 30초 권장)

## 3. 화면 흐름 & API 8종 매핑

| 순서 | 화면 | 호출 API | 핵심 동작 |
|---|---|---|---|
| 1 | 시작 화면 | ① `POST /api/v1/sessions/guest` | 사진 분석 동의(`photoConsent: true`) 체크 후 `sessionId` 발급·저장 |
| 2 | 기본 정보 입력 | ② `POST /api/v1/sessions/{sessionId}/profile-input` | 나이(14~80), 키(140~210), 몸무게(30~200, 선택), 모질 3항목 입력. 키 변경 시 `bodyAnalysisReset: true` → 전신 재분석 필요 |
| 3 | 얼굴 촬영 | ③ `POST /api/v1/sessions/{sessionId}/analyze/face` | 실시간 카메라 + 가이드 오버레이, 정지 사진 1장 전송 |
| 4 | 전신 사진 입력 | ④ `POST /api/v1/sessions/{sessionId}/analyze/body` | 촬영 또는 앨범 선택 1장 전송 (키는 세션 값 자동 사용) |
| 5 | 분석 중(로딩) | (③·④ 응답 대기) | 30초 타임아웃 처리 |
| 6 | **결과 화면** | ⑤ `GET /api/v1/sessions/{sessionId}/result` | **1회 호출로 맞춤 유형 + 추천 헤어 2종 + 추천 패션 3종을 한 화면에 모두 표시** + 하단 `disclaimer` |
| 7 | [분석 상세보기] 팝업 | ⑥ `GET /api/v1/sessions/{sessionId}/analysis-detail` | AI 판정 근거(확신도, 후보, 측정치, Size Korea 비교) 및 수정 옵션(`editableOptions`) 표시 |
| 8 | 팝업 내 결과 수정 | ⑦ `PATCH /api/v1/sessions/{sessionId}/profile` | 얼굴형·체형·모질 수정 후 적용 → 응답의 `data.result`로 결과 화면 즉시 갱신 (⑤ 재호출 불필요) |
| 9 | Moda 메인 화면 | 없음 (MVP) | 결과 화면 하단 `[Moda 시작하기]` 버튼 진입점 |
| 10 | 부스 초기화 (숨김) | ⑧ `DELETE /api/v1/sessions/{sessionId}` | 예: 로고 3초 롱프레스 → 성공/실패 무관하게 로컬 상태·사진 URI 삭제 후 시작 화면 이동 |

### 결과 화면 패션 아이템 참고
- `imageKey`: 스타일당 **대표 이미지 1장** (로컬 에셋)
- `itemKeywords`: 룩북(여러 사진)이 아니라 **추천 옷·신발 단어 5개(텍스트 태그)** (예: `["블레이저", "셔츠", "니트 폴로", "슬랙스", "로퍼"]`)

## 4. Mobile 필수 구현 규칙 (절대 누락 금지)

1. **한글 문구·유형명 하드코딩 금지**: 라벨, 유형명(`TYPE-01`~`TYPE-24`), 추천 이유, 경고 문구 등은 모두 API 응답 값을 그대로 렌더링. (`nameConfirmed === false` 가칭 배지는 대회 빌드에서 숨김)
2. **외모 평가 배제 (R-11)**: 응답의 `score`는 화면에 점수·별점·%로 **절대 표시 금지**(`rank`와 `reasons`만 사용). BMI 수치도 노출 금지.
3. **`usable: false` vs `503/504` 분기 구분 (v1.1 중요 변경)**:
   - `usable: false` (HTTP 200): 경고창(`warnings[].message`) + **재촬영만 안내** (다음 화면 이동 불가, **"직접 선택하기" 노출 금지**).
   - `503 AI_SERVER_UNAVAILABLE` / `504 AI_TIMEOUT`: `[재시도]` + **`[직접 선택하기]` 노출** → ⑦ `PATCH /profile`로 수동 선택 허용.
4. **체형 상세 Optional 필드 처리**: `status: "ANALYZED"`여도 `confidence`, `borderline`, `compareToSizeKorea`가 `null`이거나 `candidates`, `features`가 `[]`일 수 있음. 에러가 아니므로 **값이 있는 항목만 렌더링하고 없는 항목은 빈 상태 문구 없이 숨김** (최소 보장: `status`, `result`, `description`).
5. **사진 업로드 & 프라이버시 (R-01)**:
   - 서버는 사진을 저장하지 않고 즉시 파기하므로, 결과 화면에 사용자 사진 표시가 필요하면 앱의 **로컬 URI** 사용 후 초기화 시 삭제.
   - JPG/PNG, 최대 10MB, 촬영 시 `quality: 0.7` 압축 권장.
   - `FormData` 전송 시 `Content-Type` 헤더를 직접 지정하지 말 것(boundary 자동 설정).
6. **세션 만료 공통 처리**: `404 SESSION_NOT_FOUND` / `410 SESSION_EXPIRED` 수신 시 로컬 상태 초기화 → 시작 화면 이동.
7. **스타일 대표 이미지 14장 확보 (`assets/styles/`, 출처·라이선스 확인 필수, 기한 11/27)**:
   - 헤어 5종: `hair_up_style`, `hair_parted_style`, `hair_dandy_style`, `hair_crop_style`, `hair_shadow_style`
   - 패션 9종: `fashion_casual`, `fashion_dandy`, `fashion_minimal`, `fashion_city_boy`, `fashion_amekaji`, `fashion_street`, `fashion_sporty`, `fashion_gorpcore`, `fashion_vintage`
8. **Enum 대소문자 & 환경별 서버 주소 / Mock 테스트**:
   - 얼굴형·체형 Key: 소문자(`heart`, `small_inv_triangle`) / 모질 Enum: 대문자(`THIN`, `SEMI_CURLY`, `MEDIUM`).
   - 로컬 Base URL: PC·iOS 시뮬레이터 `http://localhost:8080` / Android 에뮬레이터 `http://10.0.2.2:8080` / 실기기 Expo Go `http://{PC LAN IP}:8080`.
   - Mock 헤더(`moda.ai.mode=mock`일 때): `X-Mock-Face-Shape`, `X-Mock-Body-Type`, `X-Mock-Unusable`, `X-Mock-Borderline`, `X-Mock-Body-Minimal`, `X-Mock-Delay-Ms`.

  - **구현 전제**:
    1. 핵심 MVP(API 1~8 전체 흐름) 안정화 완료 후 진행.
    2. 모바일에 AI API 키 직접 삽입 금지 → **백엔드 경유 LLM API(Gemini/OpenAI)** 또는 비용 0원 **버튼형(규칙 기반) 챗봇** 방식으로 백엔드(박준희)와 협의 필요.
    3. R-11(외모 지적·BMI 금지) 및 R-13(연예인 초상권 주의) 준수.
